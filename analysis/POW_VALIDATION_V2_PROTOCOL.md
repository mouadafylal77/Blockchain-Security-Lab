# Prospective PoW policy evaluation v2

Separate from frozen M5; no historical file is replaced. `configs/interactive/validation_protocol.json` defines 7 hash-power fractions (0,10,30,49,51,65,85%), 30 validation seeds 2001..2030, fixed/adaptive detectors, baseline/attacked/protected/honest_protected. Four nodes: a coordinated adversary, two honest miners sharing remaining work, and a passive merchant. Same total hash power and network in all modes. Six confirmations and engineering policy defaults are declared prospectively, not optimized on outcomes.

Full preparation creates 1680 evaluation configurations plus 7 prior honest calibrations (seed 3001), without executing them. Shared calibrations are conditional references, not 30 independent calibration replicates. No calibration input uses attacked observations. All runs reset detector state. New runs use public merchant notices and local adversary chain observations, unlike the explicitly archived legacy oracle. Neither the attack nor consensus is changed to force defensive success. Fixed difficulty, 300 global discoveries and 100000 ticks bound each run; no target-height stop in this evaluation.

Commands (PowerShell 7, no Python): `./scripts/run-validation.ps1` prepares a fresh directory. `-Run` executes sequentially. `-Smoke -Run` executes eight fixed-detector sanity runs (q30/q85, seed2001, four modes); those are not a statistical estimate or part of a completed full campaign. The original M5 runner/configurations are untouched.

Primary attack outcome: accepted merchant payment reversed by a published competing spend in the merchant's final local view. Report successful/failed/inconclusive separately. Non-acceptance (including false holds), remaining private state or hard-limit censoring cannot be counted as successful protection. Report acceptance fraction and delay among accepted payments alongside attack success, including attempted q=0 exposures.

Detection retains M4's explicit run x primary-family unit (4 decisions/run), including failed attempts. TP/FP/FN/TN and micro P/R/F1 are not causal attribution of each anomaly. Report merchant-local warning/action before acceptance separately from a global chain_instability alarm. Optional public silence/fork warnings can cause policy actions without matching the primary attack family; do not silently relabel those as correct identification. Distinguish first warning, first action, payment creation/inclusion, acceptance, public notice, private publication and reorganization using event sequences, values and thresholds. Non-detection latencies are null/censored, not zero.

Pair modes/detectors by seed; bootstrap whole seeds for confidence intervals, preserve all seeds and report missing/censored counts. For boundary proportions include Wilson intervals. This protocol prepares data for later analysis; no aggregate estimates or significance tests are claimed here. Use honest_protected to quantify false sanctions, acceptance loss and economic/availability costs. A synthetic coin lost differs from pool reward units and from real money. Messages/events are simulated overhead; elapsed process time is real time. No universal protection against majority PoW is claimed.
